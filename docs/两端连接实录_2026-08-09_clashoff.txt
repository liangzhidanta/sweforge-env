===== 块 1: 前置确认（Clash 关闭后的网络状态） =====
【目的】验证用户关闭 Clash 后系统代理是否真的关闭; 判断连接是否更简单。

【命令】scutil --proxy; env | grep -i proxy; ps aux | grep -iE "verge|mihomo|clash"
【输出】
  HTTPEnable : 0            <- 系统 HTTP 代理已关闭
  HTTPSEnable : 0
  SOCKSEnable : 0
  ProxyAutoConfigEnable : 0
  （env 无 proxy 变量）
  /Applications/Clash Verge.app/.../clash-verge     <- 应用进程仍在
  /Applications/Clash Verge.app/.../verge-mihomo    <- 内核进程仍在

【结论】系统代理确已关闭（HTTPEnable=0）。Clash 应用进程虽未退出但不再
拦截 127.0.0.1 -> Mac 侧命令无需再加 NO_PROXY（实测 curl 直接通）。
但 Mac 是内网 IP(10.21.190.41)、无 SSH 服务, 反向隧道仍必须——
「关 Clash」只是省掉 NO_PROXY, 并不会让连接拓扑变简单。

===== 块 5: 真实 LLM(vLLM + SFT ckpt) 驱动（本次遇 GPU 被占用） =====
【目的】尝试真实 LLM 驱动 rollout 经隧道打到 Mac Docker。本次启动失败,
原因不是连接, 而是 AutoDL GPU 正被另一进程（SFT 训练）占满。

【命令】(AutoDL) cd /root/autodl-tmp/SWE_project && PYTHONPATH=src \
  /root/autodl-tmp/conda/envs/sweforge/bin/python - < /tmp/real_llm_docker.py
【输出】（health 通过; vLLM 申请显存失败）
  health: True
  ...
  ValueError: Free memory on device (0.48/23.52 GiB) on startup is less than
  desired GPU memory utilization (0.3, 7.06 GiB). Decrease GPU memory
  utilization or reduce GPU memory used by other processes.
  RuntimeError: Engine core initialization failed. See root cause above.

【命令】(AutoDL) nvidia-smi --query-gpu=memory.total,memory.used,memory.free --format=csv; ps aux | grep sft
【输出】
  24564 MiB, 20242 MiB, 3842 MiB
  python scripts/smoke_sft.py --model ...          <- SFT 训练进程
  python -u .../scripts/sft_lora_entry.py          <- 占用 20232 MiB GPU

【结论】AutoDL GPU 当前被 SFT 训练占用, 真实 LLM rollout 需等训练结束或
调低 gpu_memory_utilization 后重试——属服务端资源问题, 非连接问题。
（历史记录: Base / 12 步 SFT 模型也未学会输出 <tool_call>, 会 AGENT_ERROR,
属模型能力问题; 连接管线本身已由块 3、块 4 证明可用。）

===== 块 6: 两端「连接提示」机制说明 =====
【目的】回答用户「两端连接上（LLM 能操作 Mac Docker）时终端有什么提示」。

Mac 侧（已实现; Mac 自有代码, 改动在
  src/sweforge/env_server/server.py 的 connection_banner_app）:
  AutoDL 第一次 POST /v1/envs（即 LLM 可操作 Docker 环境）时, Mac 终端
  打印一次:
    ================================================================
      [连接提示] AutoDL 已通过隧道连接到 Mac Docker!
      LLM 现在可以操作 Mac 的 Docker coding 环境。
      时间: YYYY-MM-DD HH:MM:SS
    ================================================================
  之后每个请求（actions/patch/verify）由 uvicorn 访问日志逐条展示。

AutoDL 侧（驱动脚本自带输出, 无需改）:
  interop_mac.py / LLMPolicy 驱动脚本会打印 health / 每步动作 /
  agent_finished / turns / patch / validate_trajectory 等, 这就是
  AutoDL 终端的连接提示。
  若 AutoDL 团队想要更显式的「已连接 Mac Docker」横幅, 可在其
  remote.py 构造时或驱动脚本里加一行打印——按铁律 Mac 不代改
  AutoDL 代码, 需 AutoDL 侧自己改（Mac 可提供建议行）。
