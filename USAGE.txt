=====================================================================
 SWE-Forge Env Server — 使用说明
 项目: sweforge-env   (Mac 侧执行环境, §8 契约 v1)
=====================================================================

【1. 这个项目是什么】
    这是 SWE-Forge 的 Mac 侧"任务执行环境"。Agent 在代码仓库里做修复，
    我们提供一套"环境"让它干活：
      - 给 Agent 一个干净的代码工作区 (env)
      - 提供 canonical 五工具: bash / search / view_file / str_replace / finish
      - 把 Agent 的改动导出成 git 补丁 (export_patch)
      - 在"全新工作区"上干净验证 (verify): 注入隐藏测试，跑 F2P / P2P，
        产出 VerificationResult（verdict / integrity_ok / reward 等）

    执行后端（Executor 抽象）:
      - LocalExecutor  默认，直接在临时目录跑，不需要 Docker（dev/CI）
      - DockerExecutor 每 env 一个非 root、无网络容器（真实隔离，需 colima/Docker）
    协议/接口与 AutoDL 逐字节一致（VENDORED.md），两端可无缝联调。

【2. 环境要求】
    - macOS (arm64 / Apple Silicon)，Python >= 3.11（本机用 base conda env,
      /opt/homebrew/Caskroom/miniconda/base，Python 3.12；wsh 是 3.8 不兼容）
    - Docker 可选: 本机经 colima 装好（`docker info` 可用即 OK）。
      colima 是 VM 方案，daemon 出网走宿主机代理: 配置见【9】。
    - 宿主 Clash 代理会拦 127.0.0.1 -> 本机内网 HTTP 都要加
      NO_PROXY=127.0.0.1,localhost（服务器/客户端/测试均如此）。

【3. 安装】
    本项目无需 pip install（包未做 editable 安装）:
      - 测试: 在项目根目录直接 `python -m pytest`（pyproject 里
        pythonpath=["src"] 已配好）
      - 脚本/服务器: `PYTHONPATH=src python ...`
    依赖（pydantic/httpx/fastapi/uvicorn/pytest/ruff）已在 base env。

【4. 跑测试】
    全部测试:

        NO_PROXY=127.0.0.1,localhost python -m pytest -q

    预期输出: 150 passed（含 vendored AutoDL 契约测试 + Docker 集成测试）。
    跑指定文件:

        python -m pytest tests/test_backend.py -v

    代码风格检查 (ruff):

        python -m ruff check src tests examples
        预期: All checks passed!

【5. 运行演示】
    a) 本地执行器（无需 Docker）:

        NO_PROXY=127.0.0.1,localhost PYTHONPATH=src python examples/demo_rollout.py

    b) 真实 Docker 容器（需 daemon + sweforge-base 镜像，见【9】）:

        PYTHONPATH=src python examples/demo_rollout.py --docker

    关键输出:
      [4] 空补丁验证 buggy 版本:   F2P=0/1  P2P=2/2  -> bug 存在且被 F2P 抓到
      [7] 修复后干净验证:         F2P=1/1  P2P=2/2  verdict=resolved
                                 integrity_ok=True  reward=1.0

【6. 起 Environment Server（§8 契约 v1）】
    Mac 侧入口（vendor 的 make_app 包 LocalDockerBackend，只监听 127.0.0.1）:

        NO_PROXY=127.0.0.1,localhost \
        PYTHONPATH=src python -m sweforge.env_server.server \
          --bundles-dir examples [--docker] [--port 8500] [--cleanup-stale 3600]

    - --bundles-dir: task bundle 注册表根目录（<task_id>/task_manifest.json）
    - 未登记的 task 走 setup-command 自建工作区（AutoDL Mock 语义）
    - --cleanup-stale SECONDS: 启动前清掉创建时间早于 SECONDS 秒的
      sweforge-managed 泄漏容器（上一轮 server 崩溃未 destroy 的; 按 age
      过滤, 不误杀刚创建的活跃容器）
    - 端点: GET /health, POST /v1/tasks/register, POST /v1/envs,
      POST /v1/envs/{id}/reset, POST /v1/envs/{id}/actions,
      GET  /v1/envs/{id}/patch, DELETE /v1/envs/{id}, POST /v1/verifications

【7. 与 AutoDL 联调（interop_mac.py）】
    拓扑（AutoDL 侧 Agent -> RemoteEnvironmentBackend -> SSH tunnel -> Mac
    server（只监听 127.0.0.1）-> Docker）:

        1. Mac 侧先起 server（见【6】）
        2. 建 SSH 隧道（AutoDL 侧执行）:
             ssh -L 8500:127.0.0.1:8500 user@mac
        3. AutoDL 侧跑联调脚本:
             python scripts/interop_mac.py --base-url http://127.0.0.1:8500

    退出码 0 = 全链路通过（health -> register -> create -> 五工具 ->
    export_patch -> verify -> AgentLoop + validate_trajectory）。
    本机自测（不 ssh，直接用同一份 AutoDL 客户端打本地 server）:
        NO_PROXY=127.0.0.1,localhost PYTHONPATH=src \
        python /tmp/autodl/scripts/interop_mac.py --base-url http://127.0.0.1:8500

【8. 常用 API（对接 AutoDL / 写自己的脚本）】
    协议是 AutoDL canonical（pydantic v2, discriminated union; 不是老的
    dict 风格 ToolAction）:

        from sweforge.env_server.docker.backend import LocalDockerBackend, load_task_bundle
        from sweforge.protocol.tools import ViewFileAction, StrReplaceAction

        task    = load_task_bundle(Path("examples/toy_cache_aliasing")).task
        backend = LocalDockerBackend(Path("examples"))   # bundles_dir = task_id 目录的父级
        env     = backend.create(task)                    # 建一个干净工作区
        backend.reset(env)                                # 丢弃改动回到 setup 后基线 (返回 None)
        obs     = backend.execute(env, ViewFileAction(path="toy_cache/cache.py",
                                                      start_line=1, end_line=20))
        obs     = backend.execute(env, StrReplaceAction(path="toy_cache/cache.py",
                                                        old_string=..., new_string=...))
        patch   = backend.export_patch(env)               # Agent 改完导出 git diff
        result  = backend.verify(task, patch)             # 全新工作区干净验证
        backend.destroy(env)                              # 销毁，清理临时目录

    五工具: BashAction / SearchAction / ViewFileAction / StrReplaceAction /
    FinishAction。VerificationResult 字段: verdict(resolved/unresolved/error),
    fail_to_pass/pass_to_pass(TestResult 列表), f2p_passed/p2p_passed,
    integrity_ok, reward, metadata。

【9. Docker（colima）与基础镜像】
    本机 colima VM（aarch64, Ubuntu 24.04, runtime=docker）已配好:
      - VM 内 DNS 修正为 192.168.5.3（colima.yaml dns + provision 脚本）
      - daemon 出网走宿主机代理 192.168.5.2:7897（systemd drop-in）
    构建基础镜像（Python 3.11 + git + pytest, 非 root uid 1000 用户）:

        docker build -t sweforge-base src/sweforge/env_server/docker/

    之后 demo/server 加 --docker 即用容器执行。镜像含 pytest 且 /workspace
    归 uid 1000；DockerExecutor 以 tar+docker cp 注入仓库快照。

【10. 目录结构】
    src/sweforge/
      schemas/ protocol/ environment/ reward/ agent/  # AutoDL canonical 契约 (verbatim, 勿改)
      env_server/
        docker/
          path_policy.py     # 路径安全: 拒绝越界/symlink/保护路径
          manager.py         # 容器 labels / 资源限制常量
          executors.py       # Executor 抽象 + LocalExecutor + DockerExecutor
          tools.py           # canonical 五工具观察渲染
          verify.py          # clean verifier（全新工作区注入隐藏测试）
          backend.py         # LocalDockerBackend: create/reset/execute/export_patch/verify/destroy
          Dockerfile         # sweforge-base 基础镜像
        server.py            # Mac server CLI: vendored make_app + LocalDockerBackend
    examples/toy_cache_aliasing/  # 示例任务 bundle
      repo/                  #   canonical buggy 快照（Agent 看到的东西 + 公开 P2P 测试）
      private/hidden_tests/  #   Mac 私有的隐藏 F2P 测试
      task_manifest.json     #   canonical TaskSpec
    tests/                   # 含 vendored AutoDL 契约测试 + Mac 自有测试

【11. 常见问题】
    Q: 提示 ModuleNotFoundError: No module named 'sweforge'
    A: 用 PYTHONPATH=src 前缀运行脚本/服务器；pytest 已配好不需要。

    Q: 本机 HTTP 起 server 后 curl / 客户端连不上?
    A: 加 NO_PROXY=127.0.0.1,localhost（宿主导 Clash 代理拦本地流量）。

    Q: 我没有 Docker，能用吗?
    A: 能。默认就是 LocalExecutor。只有需要真实隔离时加 --docker。
       要先 `docker build -t sweforge-base src/sweforge/env_server/docker/`。

    Q: reset 之后旧 observation/工作区会怎样?
    A: reset 丢弃 agent 所有修改，重建 executor 回到 setup 后基线，
       返回 None（AutoDL 契约）；env_id 不变。

    Q: 我换了一台机器 / 重新 clone，要做什么?
    A: 配好 Python >=3.11 环境 + 依赖即可；examples/ 任务数据随仓库走。
       要 Docker 的话另按【9】搭 colima + 建镜像。
